# Runbook — Rollback

Propósito: restaurar servicio o mitigar una entrega con impacto.

1. Incidente/criterio de activación: `PENDIENTE`.
2. Responsable de activación y comunicación.
3. Alcance afectado: frontend, Worker, D1, R2 o proveedor.
4. Pasos de reversión y validación posterior.
5. Tratamiento de datos no reversibles y plan de mitigación.
6. Cierre: evidencia, causa, acciones preventivas y actualización de ADR/runbook.
